# Native security and host scope

Version 0.1.1's native path installs one community package into untouched stock n8n. It does not apply the retained legacy server/editor/lifecycle/dependency/OS patches. Their exact historical scope is preserved in [legacy security provenance](legacy-security.md); those backports and previous companion qualification are not properties of the stock host.

n8n authorizes/decrypts selected credentials and performs encrypted credential persistence through its supported preAuthentication path. The plugin does not use private n8n DI or direct credential-database writes and never reads n8n's encryption key. One original Manager credential, identified by its true saved ID, grants administration. Account-only use does not. Sharing the Manager intentionally delegates administration; no invented edit-role API exists.

The host-encrypted user-chosen passphrase authenticates an AES-256-GCM random-owner-key wrap bound to the Manager ID, with a random 32-byte salt and domain-separated async scrypt (N32768/r8/p1, maxmem64MiB, one derivation at a time, at most four admitted). The hidden encrypted host root is a recoverable cache. Wrong/missing established passphrase, key wrap or owner claim never causes silent key regeneration. Runtime credentials contain only their scoped binding and delivery metadata, never a root key.

Exact credential-ID-bound encrypted binding delivery, fresh authorized host readback and durable ACK precede provider authentication/import activation. One instance-wide owner claim and OS-backed SQLite exclusive leases preserve a single token-family/reset journal. Old owner paths stay permanently occupied; unknown legacy locks are not removed or taken by age. Native model/session/catalog/reset/transport work uses tracked boundaries, and lease release follows real drain rather than asynchronous publication acknowledgements.

Provider tokens, device secrets, root keys, bindings and import JSON stay out of workflow parameters/static data, normal outputs and controlled errors. Public provider verification URL/code are deliberate exceptions. Import uses a password credential field. Normal Status/Test/editor reads remain local; explicit execution/refresh may renew. Rotating-token ownership, raw-success capture, exact identity/affinity, reset dispatch/idempotency and unknown-outcome fences remain authoritative. Never restore older token state or replay an uncertain exchange.

The package has no purchase/top-up/billing writer, no global Codex discovery, and no Platform API-key fallback. Native replay/tool batches, structured validation, public-image-address checks and finite resource bounds remain in the existing core. Trusted n8n/community code and the operator's filesystem remain part of the trust boundary. This integration is experimental, not a sandbox for malicious custom workflow code.

The native Codex Output Parser uses the existing first-error Ajv validator and a public JSON Schema parser contract. It accepts bounded object JSON, with a four-MiB input ceiling, depth 64 and 65,536 inspected properties or array slots. It never converts an untrusted result through host Zod or requests repair itself. Existing stock Zod-based parser nodes are outside untrusted-output qualification on this pinned host; use the Codex parser in an ordinary Agent or Basic LLM Chain.

The pinned host also contains a Markdown smartquotes advisory when typography is enabled. The supported basic Codex Chat route checks visible text and cumulative quote/rendering work before delivery, and refuses tools, parsers, routing and extra main output nodes before provider work because their independent host UI output cannot be intercepted by a model adapter. A controlled refusal preserves accepted-request fences and requests no retry. This protects newly generated Codex replies in the qualified route; it does not patch the host renderer, other providers, historical stored messages or arbitrary workflow code. See [current upstream Markdown advisory](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-r7fv-28h4-cvq7) and [host Zod collection advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).

Codex Wire is qualified against the versions listed in [qualification and compatibility](qualification.md). Keep n8n and its operating-system dependencies current, and review the exposure of any additional host features you enable. The package's parser and basic Chat controls cover their documented paths; they do not update host dependencies or make every stock integration safe. Package and stock-image provenance, installed metadata normalization and synthetic test limits are recorded separately. Live account entitlement, arbitrary n8n versions and the separate standalone Agents builder are outside this qualification.
