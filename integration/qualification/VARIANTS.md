# Independent loader qualification variants
Sequential fresh synthetic states using the same approved image/container/network/port scope.

The default matched image has no active custom-extension path. Merely installing the lifecycle hook does not register Codex nodes. Each variant uses a different directory beneath the approved `n8n-data` mount; no existing stand or credential is reused.

1. `QUALIFICATION_VARIANT=agents-only`, empty `QUALIFICATION_CUSTOM_EXTENSIONS`: start with an empty community package directory. Assert the loaded node registry contains no Codex node IDs and the community package API reports no `n8n-nodes-codex-chat`. Prove native n8n Agents calls use the neutral lifecycle hook and exact authenticated gateway handshake. This is the Agents-only result.
2. `QUALIFICATION_VARIANT=community`, empty `QUALIFICATION_CUSTOM_EXTENSIONS`: install `/opt/codex-wire-artifacts/n8n-nodes-codex-chat-0.0.5.tgz` with npm into this variant's actual n8n community directory, using the prepared offline public dependency cache. Follow the pinned stock installer: unpack the exact tarball, remove devDependencies/peerDependencies/optionalDependencies from its installed manifest, then npm install only production dependencies with --bin-links=false --install-strategy=shallow --ignore-scripts=true --package-lock=false. The offline cache contains only jose/Ajv/formats and their runtime dependencies. Do not install LangChain or n8n-workflow copies, even at matching versions, and do not add symlinks at the community root. Restart only the isolated n8n container. Assert editor type names are `n8n-nodes-codex-chat.codexChatModel`, `n8n-nodes-codex-chat.codexAccountTools`, `n8n-nodes-codex-chat.codexAccountRouter`, `n8n-nodes-codex-chat.codexImage`. Exercise all four through the real community loader. Assert strict object identity with host LangChain and n8n-workflow through the actual n8n loader; versions alone are insufficient. Assert no community-installed peers or extra peer symlinks. If the installation uses the protected local tarball instead of the actual registry UI route, label it manual local-tarball installation with stock installer semantics; do not claim actual UI registry installation. A synthetic private fixture registry may separately qualify that route without publishing the package.
3. Optional `QUALIFICATION_VARIANT=legacy-custom`, `QUALIFICATION_CUSTOM_EXTENSIONS=/opt/codex-wire-context/dist`: only this variant may use the legacy custom-extension path and its separately linked host peers. Label every result CUSTOM; it cannot qualify the community installer or Agents-only case.

The physical runner must resolve the actual user/community directories from the pinned n8n configuration and record them. `N8N_USER_FOLDER` supplies an isolated parent; do not assume it equals the final `.n8n/nodes` path. Image build prepares an offline npm cache from only the package production dependencies, matching the stock installed-manifest rewrite. No runtime registry/provider egress is available. The read-only cache belongs to the image; a writable cache copied beneath this variant's approved n8n-data directory avoids permission or out-of-scope writes during the isolated install.
